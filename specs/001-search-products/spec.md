# Feature Specification: 商品検索機能

**Feature Branch**: `001-search-products`

**Created**: 2026-09-09

**Status**: Draft

**Input**: User description: "商品検索機能を追加したい。キーワードとカテゴリで絞れて、一覧から詳細に飛べれば良い"

## Clarifications

### Session 2026-09-09

- Q: キーワードに複数の語が入力された場合、どのように商品を絞り込みますか？ → A: 入力全体を1つのキーワードとして部分一致させる。
- Q: 購入者が検索条件を入力した後、検索結果はどのタイミングで更新しますか？ → A: 検索ボタンを押したときに更新する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 商品を検索する (Priority: P1)

購入者は、商品名や商品説明に含まれるキーワードとカテゴリを指定して、目的の商品を絞り込みたい。

**Why this priority**: 欲しい商品を見つけることが商品検索の中心価値であり、商品詳細への導線の前提となるため。

**Independent Test**: 商品一覧でキーワードまたはカテゴリを指定して検索し、条件に合う商品だけが表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 商品が複数登録されている、**When** 購入者がキーワードを指定して検索する、**Then** 商品名または商品説明にキーワードを含む商品だけが一覧に表示される
2. **Given** 複数カテゴリの商品が登録されている、**When** 購入者がカテゴリを指定して検索する、**Then** 指定カテゴリの商品だけが一覧に表示される
3. **Given** キーワードとカテゴリの両方を指定する、**When** 購入者が検索する、**Then** 両方の条件を満たす商品だけが一覧に表示される

### User Story 2 - 検索結果から商品詳細を見る (Priority: P1)

購入者は、検索結果の一覧から選んだ商品の詳細情報を確認したい。

**Why this priority**: 検索結果を閲覧するだけでは購入判断につながらず、商品詳細への移動が検索体験に不可欠なため。

**Independent Test**: 検索結果に表示された商品を選択し、選択した商品の詳細画面が表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索結果に商品が表示されている、**When** 購入者が商品を選択する、**Then** 選択した商品の詳細画面に移動し、商品名、説明、価格、カテゴリを確認できる
2. **Given** 存在しない商品を開こうとする、**When** 購入者が商品詳細へ移動する、**Then** 商品が見つからないことを示す案内が表示される

### Edge Cases

- キーワードとカテゴリの両方を指定しない場合は、全商品を一覧表示する。
- キーワードの前後に空白がある場合は、空白を除いて検索する。
- 大文字・小文字の違いは検索結果に影響しない。
- 検索条件に一致する商品がない場合は、該当商品がないことを示す案内を表示し、空の結果として扱う。
- 未登録または利用対象外のカテゴリが指定された場合は、該当商品がない結果として扱う。
- 空白だけのキーワードは未指定として扱う。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システム MUST 購入者が商品一覧を表示できるようにする。
- **FR-002**: システム MUST 入力全体を1つのキーワードとして扱い、商品名または商品説明にその文字列を含む商品へ絞り込めるようにする。
- **FR-003**: システム MUST 登録済みのカテゴリを選択して商品を絞り込めるようにする。
- **FR-004**: システム MUST キーワードとカテゴリが同時に指定された場合、両方の条件を満たす商品だけを表示する。
- **FR-005**: システム MUST キーワードを大文字・小文字の違いを区別せずに扱う。
- **FR-006**: システム MUST 検索結果に各商品の商品名、価格、カテゴリを表示する。
- **FR-007**: システム MUST 検索結果が0件の場合、該当商品がないことを購入者に伝える。
- **FR-008**: システム MUST 購入者が検索結果の商品を選択して商品詳細を表示できるようにする。
- **FR-009**: システム MUST 商品詳細に商品名、説明、価格、カテゴリを表示する。
- **FR-010**: システム MUST 存在しない商品が指定された場合、商品が見つからないことを示す。
- **FR-011**: システム MUST 購入者が検索ボタンを押したときに指定された検索条件で結果を更新し、検索条件を変更して再検索できるようにする。

### Key Entities *(include if feature involves data)*

- **商品**: 購入者が閲覧・検索する対象。商品名、説明、価格、カテゴリ、識別情報を持つ。
- **カテゴリ**: 商品を分類する名称。商品は1つのカテゴリに属する前提とする。
- **検索条件**: キーワードとカテゴリの組み合わせ。いずれか一方または両方を指定できる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 購入者の90%以上が、キーワードまたはカテゴリを指定してから10秒以内に目的の商品を検索結果で確認できる。
- **SC-002**: 検索結果が存在する場合、購入者は検索結果の商品を1回の選択操作で商品詳細に移動できる。
- **SC-003**: 検索条件に一致する商品がない場合、100%のケースで空結果であることが明確に表示される。
- **SC-004**: 代表的な検索シナリオの受け入れテストで、キーワード、カテゴリ、両条件の組み合わせが正しい商品だけを返す成功率が100%になる。
- **SC-005**: 検索を利用した購入者が、検索結果から商品詳細を確認するまでの主要タスクを90%以上の割合で完了できる。

## Assumptions

- 対象ユーザーは認証なしで商品を閲覧・検索できる購入者とする。
- 既存の商品データとカテゴリ情報を検索対象として利用する。
- 商品一覧の初期表示は全商品とし、並び順やページ分割は既存の一覧表示に従う。
- v1では価格帯、複数カテゴリ選択、並び替え、検索履歴、候補表示は対象外とする。
- キーワードは商品名と商品説明を対象とし、カテゴリ名はキーワード検索の対象外とする。
- 商品詳細には既存の商品情報を表示し、購入処理やカート操作は本機能の範囲に含めない。
